# WhatsApp Bot Full Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the two directors and the EA run tasks, checklists, follow-up, MIS and leaves/holidays from WhatsApp. Every write is confirmed first, the numbers match the app, and Claude tokens are spent only where they're needed.

**Architecture:**
- **App rules are shared, not copied.** The rules now inside route handlers move into server modules under `lib/server/`. The routes and the bot both call those modules.
- **Bot pipeline.** Each message runs: strict command parser (no Claude) → read handlers / proposal builders → existing 1/2 confirmation → executor that calls the shared modules.
- **Fallback to Claude.** A message the parser can't match goes to Claude Haiku. Claude gets about 5 grouped tools, a cached fixed prompt, effort `low`, and its usage is logged on the outgoing `wa_messages` row.

**Tech Stack:** Next.js App Router (Node runtime, Vercel), Supabase JS (service-role client), `@anthropic-ai/sdk`, `zod`, `node:test`.

**Spec:** `docs/superpowers/specs/2026-10-27-whatsapp-bot-full-integration-design.md`

## Global Constraints

- Model is `claude-haiku-5-5`.
- Claude calls use `output_config: { effort: "low" }`, adaptive thinking (never disabled), `max_tokens` 1024 and at most 3 tool rounds.
- Every create, change and delete is only *proposed* until the user replies `1`. The existing limits stay: 10-minute expiry, at most 5 changes per confirmation.
- A permanent delete's label starts with `PERMANENT DELETE` and ends with `(cannot be undone)`.
- "remove"/"delete" never maps to cancel or complete. "done"/"complete"/"close" never maps to delete.
- Bot users are only `employees` with `role` in `super_admin`/`assigner`/`ea`, a linked `whatsapp_chat_id`, and a chat ID in `ALLOWED_CHAT_IDS`.
- Per-role limits follow the app:
  - Leaves and holidays: `super_admin` and `ea` only (`nonWorkingDayManagerRoles`).
  - Checklist done/reopen on anyone's item: `super_admin` and `ea` only. An `assigner` can do it only on their own items.
- References: tasks `#<n>` (`tasks.short_code`), checklist items `C<n>`, recurring checklist tasks `R<n>`. The parser accepts upper or lower case.
- Times are `Asia/Kolkata`; use `lib/checklist-time.js`. A task's default due time is `18:30`.
- Pure (database-free) logic lives in `.mjs` files that import with explicit `.js`/`.mjs` extensions, like `lib/wa/updates.mjs`. Only those can be imported by `node:test`, via `tests/run-tests.mjs`.
- Every route refactored in this plan keeps its exact HTTP status codes, response bodies and notifications.
- Do not run `npm run build` while `next dev` is running.
- WhatsApp message cap is 4000 characters (`lib/wa/green.js`). Lists show at most 15 rows, then `+N more`.

## Review Focus

1. **Free text that contains a command word.** For example "remove the GST line from #12's description" or "don't delete #12, just mark it done". This must not match the delete or done command; it goes to Claude. Covered by a Task 4 test.
2. **The target is gone between proposal and confirmation.** For example, a task deleted in the app after "remove #12" but before "1". The reply must be `❌ #12 no longer exists.`, never a crash or a silent ✅. Covered by a Task 7 test using a stub database client.
3. **A name that matches several people** (today "Vipul" matches Vipul Kumar and Vipul (MIS)). Every handler that takes a name must return the "matches several" question and never pick the first match. Covered by a Task 5 test.
4. **An `assigner` asking for something their role can't do** (leave, holiday, or done on someone else's checklist item). The bot must refuse at proposal time, with the same reason the app gives. Covered by a Task 7 test.
5. **A list long enough to pass WhatsApp's 4000-character cap.** It must be cut at 15 rows with `+N more`, never cut off mid-line by `green.js`. Covered by a Task 5 test.
